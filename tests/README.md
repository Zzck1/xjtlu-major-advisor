# 验证入口与数据边界

全部学生资料为合成或虚构。`fixtures/fictional-policy.json` 的机构、项目、年份、课程和门槛全部是测试专用，绝不能用于真实西浦咨询。构建器排除学生包中的整个 tests 目录。

- `scenarios.json` 保存12个验收场景的输入与预期。其原始规格中的 `actual_output=null` 表示规格文件自身不是运行日志；实际运行结果在 `../validation/model-responses/` 和 `../validation/behavior-review.json`。
- `test_eligibility.py` 运行隔离的确定性资格参照模型，验证边界分数、未知、年份/身份、只有1–2项、改答与冲突。它不是Skill宿主实际执行器，不能据此证明大模型不会偏离规则。
- `../maintenance/validate.py` 检查实际发行文件和ZIP的完整性、引用、编号、源内容一致及测试隔离。
- `../validation/platforms.md` 的P01–P09是尚待目标平台执行的操作步骤；不能以本地测试代替。

复现模型测试时建议每例创建独立临时会话，只传场景输入、Skill及必要原始资料，不把预期答案传给执行模型。资格测试仅在隔离的虚构机构语境运行。逐轮保留实际问答，并由另一审阅者按语义判定。

本版本的批量模型测试在同一个子代理上下文中逐场景模拟，显式声明各场景独立状态；并不等同于12个真正隔离的宿主会话。缺失文件场景也是显式模拟缺失，平台真实文件故障仍需P04验证。
