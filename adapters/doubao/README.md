# 豆包兼容版：上传资料后开始咨询

资料版本：0.1.2-rc1｜核验日期：2026-09-18｜状态：聊天兼容材料已提供；文件接受类型、数量/大小限制、完整读取和长对话保持待用户环境验证。

## 三步开始

1. 新建自己的豆包对话，上传 `uploads/00-核心规则与全专业简表.md` 和 `uploads/01-领域分组索引.md`。如果当前界面每次只能选一个文件，分两次上传；如果不接受 Markdown，使用包内同内容 `.txt` 文件。以界面实际限制为准。
2. 复制[启动提示词](启动词.md)的正文发送。只有顾问能够报告资料版本，并从资料中定位实际规则和索引内容，才算启动检查完成。
3. 输入 **开始选专业咨询**，一问一答。形成候选后，按顾问指出的文件名上传 `uploads/details/` 内对应领域详细档案，再形成报告。

详细分组文件从同版核心档案自动生成，编号与内容保持一致；每个专业在哪里，查 `uploads/01-领域分组索引.md`。不要因为暂未上传某个领域，就把该领域的专业从候选目录删去。

## 上传策略

首轮只使用核心规则和全专业简表，避免一次装入所有详细资料。候选涉及多个领域时逐份补充对应档案；模型读不到某项时，应明确指出缺失文件、`major_id` 和受影响判断。不能仅凭专业名称或简表完成正式排序。

核心资料、分组资料与继续咨询摘要应在同一会话中使用。若发生上下文丢失，重新提供核心资料及[继续咨询摘要](继续咨询摘要模板.md)，再粘贴[继续咨询提示词](继续咨询提示词.md)。学生可只提供有关课程信息，无需姓名、学号、身份证号或完整成绩单。

## 官方已确认与仍未确认

[豆包云盘使用须知](https://www.doubao.com/legal/ai_space)正文确认存在文件上传入口及登录要求；[豆包隐私政策](https://www.doubao.com/legal/privacy)说明对话中选中的云盘文档会作为参考资料。它们没有给出本次所需的统一文件类型、个数、大小或完整上下文保障。不能把搜索摘要里某个特定分享页显示的限额当作全平台规则。

开发时只读发现本机豆包启动器版本为 2.29.10，未打开或登录豆包会话，未上传任何资料。官方网页聊天入口本次未能提取正文，因此联网开关、附件接受范围、Markdown/TXT 读取和生成文件均未实测。**这里的 `.md` 与 `.txt` 是提供的兼容候选格式，不是已证实在所有豆包版本可上传。**如果两种文件均不被接受，可分段粘贴核心内容和相关完整档案；仍需做读取检查。

无法联网时使用包内来源和核查日期，岗位、招生或升学动态条件列为待复核。无法生成下载文件时，直接提供完整 Markdown 报告与可复制的继续咨询摘要。

## 读取抽查（首次使用前）

不要只问“你都读完了吗”。请从上传文件中分别抽取：核心文件前部的版本、资格部分的 `pending_verification` 定义、末部索引的一个条目；再从一个详细分组文件的开头、中间和末尾各选一个 `major_id`，请豆包给出对应名称、一个原文实际存在的字段和来源链接，人工对照。每次只抽查一项，避免把测试变成问卷。错误或遗漏时先补读，再继续咨询。具体记录表在[平台核验记录](../../validation/platforms.md)。

## 三份 Word 输出

默认交付三个独立 `.docx`：①决策结论与适配候选；②你的选择画像与两个重点候选的差异；③就业探索、接下来的验证行动与信息边界。需要当前平台实际具备 Word 生成及下载能力。不能生成附件时说明限制并保留三组完整正文，不把聊天文本或改后缀文件称为 Word。三份 Word 的目标客户端输出仍需实测。
